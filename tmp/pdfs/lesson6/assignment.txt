  So the phone shows a number keyboard instead of a full letter keyboard. The phone field uses

PART B — View Binding
We have created the interface. Now we need Kotlin to communicate with the views.
Previously, you may have used findViewById(). In this practical we use View Binding, which gives us a
safer and shorter way to reach every view that has an ID.

Step 3 — Open the app-level Gradle file
On the left, click the arrow beside:
 Gradle Scripts

You will see two files with similar names:
 build.gradle.kts (Project: TenantManagementSystem)
 build.gradle.kts (Module :app)

Open build.gradle.kts (Module :app). Do not open the Project one.
  Question: Which one? They look the same.
  Always the one that says Module :app. The Project file configures the whole project; the Module file
  configures your app, and that is where features like View Binding are turned on. If you edit the wrong
  one, you will see an error that android or buildFeatures is not recognised.

Step 4 — Find android { } and enable View Binding
Scroll down until you see something similar to:
 android {
   namespace = "com.example.tenantmanagementsystemgroupa"
   compileSdk = ...

     ...
 }

Inside the android { } block, add:
     buildFeatures {
       viewBinding = true
     }




                                          BBT3202 Lesson 6 Practical — Page 4
For example:
 android {

     namespace = "com.example.tenantmanagementsystemgroupa"

     compileSdk = ...

     buildFeatures {
       viewBinding = true
     }

     ...
 }

Do not put it outside android { }.
  Question: Can I put it outside android { }?
  No. buildFeatures only exists inside android { }. Outside it, you will get Unresolved reference: buildFeatures.
  Question: I already have a buildFeatures block.
  Do not create a second one. Add viewBinding = true inside the existing block.
  Question: My package name is different from the one in this guide.
  That is fine. Everywhere this guide shows com.example.tenantmanagementsystemgroupa, use your own
  package name. You can find it on the first line of MainActivity.kt.

  Question: The yellow bar disappeared before I clicked it.
  Use File → Sync Project with Gradle Files, or click the elephant icon with the blue arrow in the

PART C — Use View Binding in MainActivity
Now we connect our XML to Kotlin.

Step 6 — Open MainActivity.kt
On the left:
 app
  └── kotlin+java
     └── com.example.tenantmanagementsystemgroupa
       └── MainActivity.kt

Double-click MainActivity.kt.

Step 7 — Import the binding class
At the top of MainActivity.kt, with the other import lines, add:
 import com.example.tenantmanagementsystemgroupa.databinding.ActivityMainBinding




                                          BBT3202 Lesson 6 Practical — Page 5
Your package name may be different. The important part is the ending:
 .databinding.ActivityMainBinding

Why ActivityMainBinding? Because our XML file is called activity_main.xml. Android generates a binding
class for every layout using this rule: remove the underscores, capitalise each word, and add Binding.
 activity_main.xml → ActivityMainBinding

  Question: ActivityMainBinding is red.
  Check three things: (1) you clicked Sync Now in Step 5; (2) the import uses your package name
  followed by .databinding; (3) if both are correct, use Build → Rebuild Project. You can also click the
  red word and press Alt+Enter (Mac: Option+Enter) to add the correct import automatically.

Step 8 — Create the binding variable
Inside MainActivity, but before onCreate(), add:
 private lateinit var binding: ActivityMainBinding

So it looks like this:
 class MainActivity : AppCompatActivity() {

     private lateinit var binding: ActivityMainBinding

     override fun onCreate(savedInstanceState: Bundle?) {

  Question: What does lateinit mean?
  It means "I promise to give this variable a value before I use it." We cannot create the binding until
  onCreate() runs, so we declare it here and fill it in inside onCreate().

Step 9 — Inflate the binding
Inside onCreate(), add:
 binding = ActivityMainBinding.inflate(layoutInflater)

Then replace:
 setContentView(R.layout.activity_main)

with:
 setContentView(binding.root)

The beginning of your Activity becomes:
 class MainActivity : AppCompatActivity() {

     private lateinit var binding: ActivityMainBinding

     override fun onCreate(savedInstanceState: Bundle?) {
       super.onCreate(savedInstanceState)

         binding = ActivityMainBinding.inflate(layoutInflater)

         setContentView(binding.root)
     }
 }

  Question: My MA inactivity also has enableEdgeToEdge() and a block starting with
  ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main)) . Do I keep it?
  Delete those lines for this practical. That code looks for a view with the ID main, and our layout does
  not have one, so the app would crash when it opens.



                                               BBT3202 Lesson 6 Practical — Page 6
  Question: What is binding.root?
  The outermost view in the layout, which here is the ConstraintLayout. setContentView(binding.root)
  shows the whole layout on screen, just like setContentView(R.layout.activity_main) did before.

Step 10 — Access the views
We no longer need findViewById(). Every view that has an ID is now available through binding.
Because the XML contains:
 android:id="@+id/tenantNameEditText"

Android creates:
 binding.tenantNameEditText

Similarly:
 binding.phoneEditText
 binding.rentEditText
 binding.saveButton
 binding.tenantResultTextView

  Question: What happens to a view that has no ID?
  It does not appear in the binding class. Only views with an android:id can be reached through binding.
  Question: If my ID is tenant_name_edit_text, what is it called in binding?
  binding.tenantNameEditText. Underscores are removed and the words are joined in camelCase.

  Question: Is View Binding the same as findViewById?
  It does the same job, but more safely. With findViewById, a wrong ID still compiles and then crashes
  when the app runs. With View Binding, a wrong ID shows a red error before you even run the app.

Step 11 — Make SAVE work
Inside onCreate(), underneath setContentView(binding.root), add:
 binding.saveButton.setOnClickListener {

     val name = binding.tenantNameEditText.text.toString()

     val phone = binding.phoneEditText.text.toString()

     val rent = binding.rentEditText.text.toString()

     binding.tenantResultTextView.text =
       "Tenant: $name\nPhone: $phone\nRent: KSh $rent"
 }

  Question: What does $name do inside the quotes?

PART D — Enable Data Binding
View Binding and Data Binding are related, but they solve slightly different problems.
                                                View Binding                           Data Binding
 What it does                                   Lets Kotlin reach the views            Lets the XML read data directly
 Direction                                      Code → views                           Data → views
 Layout change needed                           None                                   The layout is wrapped in a
                                                                                       <layout> tag
 Build speed                                    Fast                                   Slower (needs the kapt plugin)



                                                 BBT3202 Lesson 6 Practical — Page 8
                                      View Binding                           Data Binding
 Typical use                          Most screens                           Forms and screens that display
                                                                             objects


Look at Step 11 again. Kotlin does two jobs there: it collects the input, and it decides exactly how the
result text looks ("Tenant: $name\nPhone: ..."). With Data Binding, Kotlin only hands over a Tenant object,
and the XML decides how to display it.
 View Binding:   Kotlin ──builds the text──▶ TextView

 Data Binding: Kotlin ──gives a Tenant──▶ XML ──displays it──▶ TextView


Step 13 — Turn on Data Binding
In the same file, find:
 buildFeatures {
   viewBinding = true
 }

and change it to:
 buildFeatures {
   viewBinding = true
   dataBinding = true
 }

Click Sync Now.
  Question: After syncing, I see a warning about kapt and Kotlin language version 2.0.
  That is a warning, not an error. The project will still build and run.
  Question: Do I need both viewBinding and dataBinding?
  You can keep both. We still use binding.saveButton and the EditTexts exactly as before, and Data
  Binding adds the ability for the XML to display data.

 com.example.tenantmanagementsystemgroupa

 Tenant

Do not type .kt; Android Studio adds it automatically. Choose Class and press Enter.
Your package should now contain:
 com.example.tenantmanagementsystemgroupa
 ├── MainActivity.kt
 └── Tenant.kt




                                       BBT3202 Lesson 6 Practical — Page 9
  Question: I right-clicked and only see "New → File" or "Package".
  Make sure you right-clicked the package (com.example.tenantmanagementsystemgroupa), not the
  kotlin+java folder or the res folder.

Step 15 — Write the Tenant class
Open Tenant.kt and replace its contents with:
 package com.example.tenantmanagementsystemgroupa

 data class Tenant(
   val name: String,
   val phone: String,
   val rent: String
 ){
   fun summary(): String {
      return "Tenant: $name\nPhone: $phone\nRent: KSh $rent"
   }
 }

The three properties match the three fields on our screen: name, phone and rent.
  Question: What does data class mean?
  A class whose main job is to hold data. Kotlin writes useful code for you automatically, for example a
  readable toString(), so printing a tenant shows its values.
  Question: What is summary() for?
  It describes how a tenant should be shown as text. The XML will call it in Step 19. Notice it's the
  same text we built inside MainActivity in Step 11, but now it belongs to the Tenant.
  Question: Why is rent a String and not a number?
  Because for now we only display it. When we start calculating totals on the dashboard, we will store it
  as a number.

Open activity_main.xml and make sure you are in Code view.

 androidx.constraintlayout.widget.ConstraintLayout

Your file now starts like this:
 <?xml version="1.0" encoding="utf-8"?>

   xmlns:app="http://schemas.android.com/apk/res-auto">

    <data>

      android:layout_width="match_parent"
      android:layout_height="match_parent">

and the very last line of the file is now:
 </layout>

  Question: I don't see "Convert to data binding layout".
  Make sure your cursor is on the root ConstraintLayout tag, not on a TextView inside it. Also check
  you clicked Sync Now in Step 14. If it still doesn't appear, you can type the <layout> and <data> tags
  by hand: move the two xmlns: lines from the ConstraintLayout up to <layout>, and add </layout> at
  the very end.
  Question: Where did xmlns:android and xmlns:app go?
  They moved up to <layout>. <layout> is now the outermost tag, and those declarations must be on the
  outermost tag.
  Question: What is <data> for?
  It is where you list the objects the layout is allowed to use. Right now it is empty. We fill it in the next
  step.

Step 17 — Declare the tenant variable
Inside the empty <data> </data>, add:
    <data>
      <variable
        name="tenant"
        type="com.example.tenantmanagementsystemgroupa.Tenant" />
    </data>

This tells the layout: "You can use a Tenant object, and inside this XML it is called tenant."
  Question: What is the difference between name and type?
  name is what we call the object inside the XML (tenant). type is the full address of the class: your
  package name plus the class name. It must match your package exactly.

Step 18 — Bind the result TextView to the tenant
Scroll down to tenantResultTextView. Find this line:
      android:text="Saved tenant will appear here"

Replace it with these two lines:
      android:text="@{tenant.summary()}"
      android:hint="Saved tenant will appear here"




                                          BBT3202 Lesson 6 Practical — Page 11
Your TextView now looks like this:
   <TextView
     android:id="@+id/tenantResultTextView"
     android:layout_width="0dp"
     android:layout_height="wrap_content"
     android:text="@{tenant.summary()}"
     android:hint="Saved tenant will appear here"
     android:textSize="18sp"
     android:padding="16dp"
     android:layout_margin="24dp"
     app:layout_constraintTop_toBottomOf="@id/rentEditText"
     app:layout_constraintStart_toStartOf="parent"
     app:layout_constraintEnd_toEndOf="parent" />

  Question: What does @{ } mean?
  It is a Data Binding expression. Anything inside @{ } is read from your data. @{tenant.summary()}
  means "call summary() on the tenant, and show the result here."
  Question: Why did we change the text to a hint?
  When the app first opens, no tenant has been saved yet, so there is nothing to display. A hint is grey
  placeholder text that shows only when the TextView is empty. As soon as a tenant is saved, the real
  text replaces it.
  Question: Won't tenant.summary() crash when there is no tenant yet?
  No. Data Binding is null-safe. If tenant is empty, the expression simply produces no text, and the hint
  is shown.
  Question: The design view no longer shows "Saved tenant will appear here" in black.
  It shows it in grey now, because it's a hint. The real text only exists when the app runs.




PART G — Give the layout a Tenant from Kotlin
Step 19 — Update the SAVE code
Open MainActivity.kt. Find the SAVE block from Step 11.
Replace these lines:
   binding.tenantResultTextView.text =
     "Tenant: $name\nPhone: $phone\nRent: KSh $rent"

with:
   val tenant = Tenant(name, phone, rent)

   binding.tenant = tenant

Your complete MainActivity.kt:
 package com.example.tenantmanagementsystemgroupa

 import android.os.Bundle
 import androidx.appcompat.app.AppCompatActivity
 import com.example.tenantmanagementsystemgroupa.databinding.ActivityMainBinding

 class MainActivity : AppCompatActivity() {

   private lateinit var binding: ActivityMainBinding

   override fun onCreate(savedInstanceState: Bundle?) {
     super.onCreate(savedInstanceState)



                                            BBT3202 Lesson 6 Practical — Page 12
         binding = ActivityMainBinding.inflate(layoutInflater)

         setContentView(binding.root)

         binding.saveButton.setOnClickListener {

             val name = binding.tenantNameEditText.text.toString()

             val phone = binding.phoneEditText.text.toString()

             val rent = binding.rentEditText.text.toString()

             val tenant = Tenant(name, phone, rent)

             binding.tenant = tenant
         }
     }
 }

  Question: Where does binding.tenant come from?
  From <variable name="tenant" .../> in the XML (Step 18). Every variable you declare in <data> becomes
  a property on the binding class.
  Question: binding.tenant is red.
  Rebuild the project (Build → Rebuild Project) so Android regenerates ActivityMainBinding with the
  new variable. If it is still red, check that the <variable> name in the XML is exactly tenant.
  Question: Do I still use ActivityMainBinding.inflate(...) now that it's Data Binding?
  Yes. The same line works for both. ActivityMainBinding now has everything from View Binding (the
  views) plus the tenant variable from Data Binding.
  Question: Why is this better than Step 11?
  In Step 11, MainActivity decided how a tenant looks on screen. Now MainActivity only creates the
  Tenant and hands it over. How a tenant is displayed lives in the Tenant class and the XML. When the
  app grows, the same Tenant can be shown on other screens without rewriting that text each time.
